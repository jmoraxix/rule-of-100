Owner request: "stop the timer by default at 0 and allow overtime with the start button". It holds
on the server, so it also works with the app closed. Also closes F01 (`timer_pause` FOR UPDATE) and
the owner's production feedback on the T10 layout.

**Done**

- Migration `supabase/migrations/20261007000000_timer_stop_at_zero.sql`:
  - `daily_entries.overtime boolean not null default false`. Clients can't write it (no UPDATE grant
    on `daily_entries`); only `timer_resume` sets it.
  - Default cap: `_pause_stale` (already run first by every RPC via `_ctx`, `create_challenge`,
    `abandon_challenge`) now also folds a non-overtime timer that reached 6000, at the crossing
    instant: `value` = 6000, `completed_at` = crossing, `timer_started_at` = null. A past-day timer
    still stops at its local midnight, whichever comes first. `_fold` also clamps to 6000 without
    overtime (defense in depth). The select takes `FOR UPDATE OF e` so two concurrent sweeps can't
    double-fold.
  - `goal_progress.today_value` caps live at 6000 for minutes goals not in overtime. New columns
    `overtime` and `timer_capped` (running, not overtime, reached 6000, not yet folded).
  - Overtime: `timer_resume` sets `overtime = overtime or value >= 6000`. Once-per-day start
    unchanged (`timer_start` always begins at 0, so it never enables overtime).
  - `timer_pause` locks the entry `FOR UPDATE` (F01). Not covered by a test: the lock only matters between two concurrent transactions, and a pgTAP file runs in a single session/transaction, so it can't observe one blocking the other.
  - Backfill: minutes entries already past 6000 (paused or running) get `overtime = true`, so
    in-flight production timers keep their time.
  - Replaced functions keep `search_path = ''`; EXECUTE re-revoked from `public, anon`.
- pgTAP `progress.test.sql`: 50 → 58. 116 tests in total.
- UI (`src/components/daily.tsx`, `src/lib/goals.ts`):
  - A non-overtime timer stops at `00:00` (not ticking), also locally before the server folds it.
  - One small control inside the ring, below the time, in a fixed slot: Start / Pause / Resume /
    "Start overtime" (calls `timer_resume`). Same in landscape. The T10 big Start/Resume button and
    separate Pause button are gone.
  - Overtime shows `+MM:SS` in the inverted state (T10). The 0-beep is kept. Focus/visibility re-sync
    from `goal_progress` was already there.
  - Owner feedback: ring sized with `min(vw, vh)` so it always fits (checked: no overflow at
    390×844, 844×390, 360×640); `%` label removed; count `+1` is now a `+` glyph button next to the
    number with the app's button style (`.btn`), `aria-label="Add 1"`, 70 px.
  - `parseSettings` coerces to strict booleans (`=== true`), security MINOR from #10.
- `src/app/icon.svg`: monochrome app icon.

**Decisions**

- Reused the T03 lazy-fold path instead of a scheduler: the credit is deterministic (exactly 6000 at
  the crossing instant), so it doesn't matter when the next RPC folds it. Until then the view shows
  it capped. No pg_cron needed.
- `timer_running` keeps its T03 meaning (row still has a start time); the UI uses `timer_capped` to
  show stopped. Not renaming keeps the read model backward compatible.
- `timer_pause` on a timer that was already capped raises `timer is not running` (unchanged
  behavior). The UI never offers Pause at 0, so only a tap at the exact second could hit it, and it
  re-syncs.
- Midnight test fixture now runs in overtime, so it still proves the midnight cap (6500) rather than
  the 6000 cap.
