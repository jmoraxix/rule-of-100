Closes T02 security review findings 1–5 (#6).

**Decisions**

- **`start_date` from SQL**: `create_challenge` takes no date. It uses today in `profiles.timezone`,
  so the day count can't be inflated (invariant 5, review finding 1).
- **Status only `active → abandoned` from the client** (`abandon_challenge`); `completed` is set
  by the functions when the 100th day is completed. Abandoned/completed can't be reactivated
  (finding 2). Abandoning stops a running timer on that goal, so it can't block other timers.
- **Timezone frozen after insert** (finding 3): the simplest way to stop day-boundary games. A
  later "I moved" flow can be a function with its own rules.
- **Shared `_ctx` prelude**: caller check, stale-timer fold, ownership/active/unit checks, local
  today. One place, so every RPC applies the same rules. Not-owned and nonexistent return the same
  `challenge not found` (no oracle).
- **Stale timers capped at local midnight, folded lazily** on the user's next RPC (`ponytail:`
  comment in the migration). The credit is deterministic, so a late fold gives the same result. If
  an RPC raises, its fold rolls back too, which is harmless for the same reason.
- **`completed_at` on timers is the exact crossing instant** (`started_at + (6000 − old value) s`),
  not the pause time, so it never depends on when the user pressed pause.
- **Once-per-day start** = refuse if today's entry exists, with an explicit error (the unique
  `(challenge_id, entry_date)` constraint is the backstop). A second running timer gets a clear
  error before the partial unique index would.
- **`_local_date(tz, ts)` takes the instant** so tests cover midnight/timezone edges. The view
  inlines the same expression because an invoker view can't call a revoked helper.
- **Streak** = gaps-and-islands over completed dates ending today (if complete) or yesterday.
  Missed days don't end the challenge (owner decision); they only reset the streak.

**Out of scope**: UI, auth, a pg_cron sweep for stale timers, what happens after Day 100 (open
question 1).
